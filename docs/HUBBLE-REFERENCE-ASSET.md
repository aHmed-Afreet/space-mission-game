# Hubble reference model and decoder

Mission 8 lazily imports the GLTF/Draco loader and requests the unchanged local [Hubble GLB](../public/assets/models/hubble-11ebb4ee-e5ba4de15c7d.glb). [The manifest](../src/presentation/assetManifest.ts) retains the pinned original URL, hash, version, DigitalSpace / NASA credit and asset-specific usage evidence. [Distributed attribution](../public/assets/models/ATTRIBUTION.txt) is readable offline. NASA does not endorse this game; the model has no blanket NASA public-domain or SPDX assignment.

The exact reviewed GLB requires `KHR_draco_mesh_compression`. A bare `GLTFLoader` rejects it with `No DRACOLoader instance provided`; that previously left the procedural fallback visible on every load. The GLB is glTF 2.0 with 7,672 mesh triangles before node instances, five materials and embedded images. `EXT_texture_webp` is optional and has embedded PNG fallbacks.

The local decoder files are unchanged copies of `three 0.186.1/examples/jsm/libs/draco/gltf`. All three hashes independently match three's r186 commit `9b4a2ac29c63ccb43fd51c5661f2f873ac2c39b8`; no separate Draco release number is inferred. [The retained notice](../public/assets/draco/three-0.186.1-gltf/NOTICE.txt), upstream README, full LICENSE, AUTHORS and copyright source record Apache 2.0 and the upstream third-party notices. three's MIT license does not replace Draco's license. The installed loader selects WASM plus its wrapper by default and has the copied JavaScript decoder as its non-WASM fallback.

The loader has one worker and belongs to one worksite request. Success, failure and scene disposal release it. The pinned r186 loader needs a small guarded lifetime adapter: upstream `dispose()` does not prevent a pending decoder initialization from creating a later blob URL or worker. The adapter guards initialization and queued worker posts, rejects active worker promises on disposal and releases a late blob. A scene returned after disposal releases its own resources. Accepted geometry detaches before worksite disposal, and the existing paused redraw happens only after a valid model is attached.

The original model's maximum-axis extent is normalized to 3.1 world units and centred. Its pivot is translated by `y=1.35,z=1.4` relative to the unchanged worksite at `(2.4,0,15)`. No orientation correction or physically accurate Hubble scale is claimed. Existing procedural service hardware, reachable service face, indicator, physics and mission objectives retain their original positions and behavior.

The model, decoder trio and license/credit files are included in the existing offline service-worker list. All paths start with `./assets/`, so a deployment subpath stays within its own origin/base. The list is a pure manifest export and does not import three into Vite's configuration. The app's existing lazy chunks, privacy file and service-worker update policy remain in that list. Precache downloads files; it does not initialize the loader or decode a model.

`public/_headers` currently sets security/privacy response headers without a Content-Security-Policy. The decoder uses a blob Web Worker and WebAssembly compiled from downloaded bytes; these are allowed by the current policy. Any future CSP must explicitly support same-origin asset fetches, `worker-src blob:` and the browser's WebAssembly compilation policy (usually `script-src 'wasm-unsafe-eval'`). The JS decoder fallback still needs a blob worker. No broad `unsafe-eval` permission or cross-origin decoder host was added. Browser proof of actual decoding, the rendered service-face fit, offline/subpath loading and sustained device behavior remains separate acceptance evidence.
